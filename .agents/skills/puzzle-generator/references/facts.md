# Facts 格式、来源与语义审核

真实校验入口：`src/lib/puzzle-facts.ts`。下列为生成要求；程序只检查结构与引用存在，不证明语义正确。

| 字段 | 要求 |
| --- | --- |
| `id` | `F` + 非零开头正整数，题内唯一；稳定编号，删除后不复用 |
| `text` | trim 后 1–120 字符，一个事实命题 |
| `kind` | `explicit` / `derived` |
| `quote` | 可选 1–80 字符；explicit 必填，来自汤面或汤底原文 |
| `depends_on` | 最多 8 个 Fact ID；derived 至少一个，不能缺失/自引用/成环 |
| `note` | 可选，最多 160 字符；本 skill 要求新 derived 填写简短、完整推导链 |
| `status` | `draft` / `approved` / `needs_review` |

Facts 总数最多 60（写入 RPC 的限制）。ID 不要求连续；不要把 key point 的数字 ID 当成 Fact ID。完整题目中的评分点和证据允许相关，但职责不同。

## 原文事实也编号

假设虚构汤底为：“柜子里只放着一把钥匙。小林拿走了这把钥匙。”

```json
[
  {
    "id": "F1",
    "text": "小林拿走钥匙前，柜子里只放着一把钥匙。",
    "kind": "explicit",
    "quote": "柜子里只放着一把钥匙",
    "status": "draft"
  },
  {
    "id": "F2",
    "text": "小林拿走了柜子里的那把钥匙。",
    "kind": "explicit",
    "quote": "小林拿走了这把钥匙",
    "status": "draft"
  },
  {
    "id": "F3",
    "text": "小林拿走钥匙后，柜子在这一刻是空的。",
    "kind": "derived",
    "depends_on": ["F1", "F2"],
    "note": "柜内原本只有该钥匙，取走后当刻没有剩余物品；不推断之后发生的事。",
    "status": "draft"
  }
]
```

原文允许直接作为 `text`，也可忠实整理指代、标出原文明示的时间，不能扩大范围。`quote` 必须是连续原文片段，不得用概括或多个不相邻片段拼接。当前校验忽略空白、标点与符号，匹配汤面或汤底；不会容忍实词替换。

## 推导事实的准入

- 每一步来自当前故事原文、依赖 Fact 或不增添故事设定的常识。必须审核依赖是否足够，而非只看编号存在。
- 不将“可能/常见/合理猜想”升级成确定事实；不凭行为推测未交代的情绪、动机、疾病或历史。
- 现实事实、人物信念、别人对人物说的话分别记录，保留否定与引述范围。例如“朋友骗他说大家都受伤”不能写成“大家都受伤”。
- 不凭未提及写“从未发生/只有/绝不/某人没有相信”；原文明确的排他条件才可保留。
- 不用另一个真实子事实替代完整因果。例如“朋友鼓掌”不能单独证明“朋友能看见”。
- 不生成模型指令、示例答案标签、评分容错或“这条问题无关”作为 Facts。

## 版本与审核状态

新内容为 draft。既有 approved 仅在故事、该条含义与依赖均未变化时保留；改变事实含义不应沿用旧编号伪装为同一证据，新增编号，保留修改说明。故事变化后对原批准内容重新审核；检查所有传递依赖。

当前运行时：整份 Facts 有任何校验错误时返回空证据列表；校验通过后只选择 approved。批准事实不能依赖 draft/needs_review。仅给出 draft 的预览不会自动增强线上 ask。

进入 prompt 时 explicit 是 `F1 内容`，derived 是 `F3 [derived from F1, F2] 内容`；`quote` 和 `note` 是审核材料，不进入该 Facts prompt。因此必要推理结论要写在 `text`，不能只藏在 note。

## 人工检查

检查原文覆盖、每条命题独立性、推导链、时间与认知范围、重复和矛盾。出现原文未交代的关键信息时指出缺口；编辑已有故事不能自行补写。若用户授权创作/修订故事，先修改可审核汤底，再重建受影响证据。用户批准的具体内容和状态变更需要保存为可回读文件。
