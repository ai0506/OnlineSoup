# Ask 新旧架构对比

整理日期：2026-10-14。本文说明当前代码支持的两套 ask 引擎，以及已有预览评估的结果与局限。面向系统理解，不展开接口参数或 prompt 全文。

## 1. 架构上的变化

| 维度 | v1：严格／推断双路 | v2：A／B1 证据验证 |
| --- | --- | --- |
| 分工 | 两路分别做完整答案分类，侧重点不同 | A 做问题理解与分类；B1 只检查证据 |
| 并发 | 严格、推断同时开始 | A、B1 同时开始，B1 不看 A 的结果 |
| 主要材料 | 汤面、汤底、作为隐含事实的评分点、各路 examples、同题上下文 | 汤面、汤底、独立的已批准 Facts；A 看本题 examples，B1 不看示例答案 |
| 历史用途 | 同题问答参与主持上下文 | 少量玩家问题仅用于指代，不把历史 AI 答案当作证据 |
| 直接采用 | 双路标签一致 | yes+支持、no+反驳、irrelevant+无法确定 |
| 模糊问题 | 仍按双路分类比较 | A 返回 ambiguous 时直接返回，不等待 B1 |
| 冲突 | 仲裁主要读取两路标签 | 仲裁读取命题、理由与引用并重新判断 |
| 可复用答案 | 正常双路一致的稳定 yes/no 进入后续筛选 | A 与 B1 一致的稳定 yes/no 进入后续筛选 |
| 缓存范围 | 题目与旧引擎范围 | 题目、新引擎与内容版本范围 |
| 必要验证失败 | 按原有单路／提供方备用规则处理 | 主持封装回退 v1，标记失败来源，不写新缓存；仍失败则退款 |

两路“独立”表示任务与候选结果隔离，并不表示来自不同模型、训练数据或统计上独立。B1 验证的是完整命题的证据，不判断细节是否属于主线，也不承担问法分类。

程序核对 B1 引用是否存在于题目材料，但引用存在不等于推导正确。新架构增加可追查的证据结构，不能消除模型相关错误。

v2 没有 B2 联系探索分支。A/B1 在普通路径仍是两次并发调用，冲突时增加一次串行仲裁。ambiguous 提前返回只缩短等待，B1 已发起，不能按一次调用计费。

网页与 CLI 共用房间 AI 执行器。`ASK_ENGINE` 只有显式为 `v2` 才走新引擎，默认 `v1`；hint 和 reason 不随该开关改成 A/B1 流程。

## 2. 已有评估条件

- 日期：2026-10-13，Vercel Preview，新加坡区域 sin1。
- 两轮均为相同 56 个问题：生日 25、雨伞与电梯 7、虚构边界题 24。不能合并为 112 道独立题目。
- 同题对照旧、新引擎；新引擎附带当时整理的 Facts。因此比较的是引擎、prompt 与证据材料的整体配置，不是只改变调度方式的消融实验。
- 用例针对既有错误和边界，已参与 prompt 调整，不是未见测试集，也不是生产随机流量。
- 评估直接调用受保护的内部模型接口，不执行房间扣费、消息落库或玩家页面刷新。
- 此次整理只读取已有报告和原始 JSON，没有新发起付费调用。预览试跑不证明生产启用。

原始材料保留在本地 `ai-error/10-13/ask-v2-eval-b1only-run1.md` / `.json` 与 `ask-v2-eval-b1only-run2.md` / `.json`，该目录按项目规则不入 Git。本文仅保留聚合数据，不公开题目、汤底或内部模型理由。

## 3. 用时

| 指标 | 旧第 1 轮 | 新第 1 轮 | 旧第 2 轮 | 新第 2 轮 |
| --- | ---: | ---: | ---: | ---: |
| 客户端总往返 P50 | 1,927 ms | 2,023 ms | 1,797 ms | 1,924 ms |
| 客户端总往返 P95 | 2,707 ms | 2,863 ms | 2,514 ms | 2,824 ms |
| 最长总往返 | 3,453 ms | 3,232 ms | 2,992 ms | 2,991 ms |
| 记录到的调用失败 | 0 | 0 | 0 | 0 |

P50 为中位数，P95 为约 95% 的观测不超过的值。总往返包含客户端网络和评估接口内的模型、摘要处理，不是实际房间端到端耗时。

新引擎总往返 P50 分别增加约 5.0%、7.1%，P95 分别增加约 5.8%、12.3%。本次不能说新方案整体更快；最长值也不足以代表生产长尾。

每轮新引擎路径均为：47 题 A/B1 一致、4 题冲突仲裁、5 题 ambiguous 直接返回。关键路径可理解为：

- 一致：等待 A 与 B1 中较慢的一路；满足条件时还要生成事实摘要。
- 冲突：等待两路后，再等待仲裁。
- ambiguous：只等待 A，但 B1 已调用。
- v2 失败回退：还可能增加 v1 调用和等待，不在这两轮零失败样本中体现。

**原报告“判定耗时”不适合直接跨引擎比较。** `src/lib/ask-eval.ts` 中旧引擎在 `askDeepSeekHost` 返回后记时，已经包含内部事实摘要；新引擎在 `runAskV2` 返回时记时，之后才单独生成摘要。原报告对应 P50 为旧 1,259 / 1,224 ms、新 1,049 / 968 ms，不能据此声称判定提速。原始报告保持原样，本文说明其测量边界。

后续应统一定义“纯判定完成”“摘要完成”“事务完成”“客户端可见”的时间点，并分别记录缓存命中、直接采用、仲裁、回退的 P50/P95。

## 4. 成本

下表来自原始 JSON 的 usage 汇总。未缓存输入与提供方记录的 `prompt_cache_miss_tokens` 一致；它和系统问答缓存命中是两种不同概念。

| 日志用量 | 旧第 1 轮 | 新第 1 轮 | 旧第 2 轮 | 新第 2 轮 |
| --- | ---: | ---: | ---: | ---: |
| 输入 token | 261,675 | 135,362 | 257,826 | 138,760 |
| 其中缓存输入 | 241,387 | 89,472 | 237,675 | 116,096 |
| 未缓存输入 | 20,288 | 45,890 | 20,151 | 22,664 |
| 输出 token | 3,508 | 5,643 | 3,406 | 5,833 |

记录到的总输入减少约 46%–48%，但未缓存输入和输出均增加。因此，不能用“输入少一半”推导“账单少一半”。实际费用需要按提供方分别汇总：

> 缓存输入量 × 缓存输入单价 + 未缓存输入量 × 未缓存输入单价 + 输出量 × 输出单价。

还要完整计入摘要、仲裁、提前返回后继续执行的 B1、重试和回退。当前没有实际账单核对，也没有固定单价快照，本文不估算人民币费用。

A/B1/仲裁的公共前缀有助于同题后续请求复用提供方上下文缓存，但效果受预热、调用先后、材料长度和流量影响。旧引擎这两轮缓存命中量很高，不能把它与新引擎不同的缓存状态忽略后比较费用。

评估器按请求临时捕获 usage 日志；ambiguous 提前返回时，B1 可能仍在运行，不能保证相关用量完整归入本次样本。因此这些数据是日志观测，不是结算依据，原报告平均调用数也不应被当作账单调用数。

另外，玩家积分是产品资源计费，与平台实际模型费用分开。一次玩家请求内的 A、B1、仲裁与引擎回退不会按模型调用次数向玩家追加积分扣费。

## 5. 准确性

| 分组 | 题数 | 旧第 1 轮 | 新第 1 轮 | 旧第 2 轮 | 新第 2 轮 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 生日 | 25 | 22 | 25 | 21 | 25 |
| 雨伞与电梯 | 7 | 6 | 7 | 7 | 7 |
| 虚构边界题 | 24 | 20 | 23 | 19 | 24 |
| 合计 | 56 | 48 | 55 | 47 | 56 |
| 样本准确率 | — | 85.7% | 98.2% | 83.9% | 100% |

两轮分别多答对 7、9 题，提升 12.5、16.1 个百分点。改善主要见于有依据推断、完整命题边界、复合问题、指代和二选一；某些“否／与此无关”边界允许多个期望标签，以评估用例的判定标准为准。

新引擎第一轮仍有一题未通过，第二轮通过，说明输出有随机波动。当前结果支持“在这组回归样本和配置上更好”，不能支持“全题库 100% 正确”或“架构本身必然带来同等提升”。

后续验证至少要区分：

- A 初判、B1 证据正确性、仲裁与最终标签，不能只报最终准确率。
- 纠正了多少初判错误，又新增了多少错误；两路一致但共同错误也要计入。
- 误答 yes/no、漏掉可推导答案、模糊问题误判，以及失败／回退率。
- 未参与调优的独立题目、多个重复轮次与生产抽样。

## 6. 当前可支持的结论

新架构把分类与证据验证分工，提供了更清晰的错误定位与审核边界；已有针对性回归样本显著改善。它没有减少普通路径的基本调用次数，本次总往返略慢；输入更短但未缓存输入和输出更高，实际费用是否下降尚未确认。

代码支持新旧切换、回退、Facts 和版本隔离。是否在生产部署、迁移是否应用、题库证据是否批准、实际流量是否走 v2，均需另外核验。当前材料不替代生产验收。
